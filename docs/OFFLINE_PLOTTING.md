# 离线数据解析与绘图

基于同事的 STM32/FPGA V3 采集版增加。采集流程和 TCP 缓冲保持 V3 行为；离线解析不访问设备，不发送指令，也不修改记录文件。

## 使用

1. 打开软件，点击右上角 **解析 HEX / 绘图**，不需要先连接 STM32。
2. 在弹窗中点击 **选择 HEX 文件**，选择已经记录完成的 `capture_*.hex`。
3. 等待解析完成。上图为电压 V，下图为电流原始计数，横轴为时间 ms。
4. 用图下工具栏缩放、平移、返回视图或保存 PNG/PDF 等图片。
5. 也可输入采样点起点和终点，点击 **显示范围**；范围为左闭右开 `[起点, 终点)`，起点从 0 开始。
6. **全局概览**恢复整个记录，**纵轴自适应**调整当前范围的纵轴。

## 已确认的格式和换算

一个记录单元为 8 个 ASCII HEX 字符，解析为 4 个字节：

`电压高字节、电压低字节、电流高字节、电流低字节`

两个通道都是无符号、大端。不是逐个 ASCII 字符的十进制码值。

示例 `08000ABC` → 字节 `08 00 0A BC` → 电压原始值 2048、电流原始值 2748。

- 电压：`V = (raw × 2 / 4096 − 1) × 6`。raw 0 对应 −6 V，2048 对应 0 V，4095 对应 5.9970703125 V。
- 电压原始值范围应为 0–4095。超过时明确报错，不擅自屏蔽高位。
- 电流：暂时不做量程或零点换算，显示 0–65535 原始计数，图中明确标注 `raw counts`，不是 A。
- 每通道采样率：100 MHz，点间隔 10 ns。第 n 组样本对应 `n / 100000000` 秒，两通道共用该时间位置。
- 每组 8 个 HEX 字符，因此 8,000,000 字节的紧凑 ASCII HEX 文件包含每通道 1,000,000 点，对应 10 ms 采集时长。

## 大文件与完整性

- 文件在后台线程分块解析，有进度显示，可取消。
- 支持大小写 HEX、ASCII 空白（空格/换行等）和开头的 UTF-8 BOM。
- 不支持 Intel HEX 地址记录、带时间戳的日志、控制指令回复和帧头。应选择 V3 自动采集生成的纯 ADC `.hex`。
- 非 HEX 字符、末尾不足一组、空文件以及解析过程中发生截断/变化的文件会明确报错。
- 本版源文件上限 1 GiB。160 MB ASCII 文件需要约 80 MB 解码样本内存，另有解释器、绘图等开销。
- 原始样本全部保留在内存。每次绘图最多约 6000 点，大范围使用每个区间内两个通道的最小值和最大值及首尾点，保留尖峰；它不是平均滤波，也不是原始完整曲线的全部顶点。
- 放大后重新从原始样本选点。范围少于点数预算时逐点绘制。图下状态会标明“抽稀概览”或“全部采样点”。
- 保存图片保存的是当前视图及其显示精度，原文件不变。该功能不校验设备上游采样是否缺失；请同时检查采集 JSON 中的完整性结果。
- 解析大文件仍会使用 CPU/内存，建议在采集完成后分析；离线线程不会占用接收线程，但不承诺在资源不足时毫无影响。

## 开发验证

`python -m unittest discover -s tests -v` 验证字节序、通道顺序、真实电压换算、100 MHz 时间轴、格式错误、取消和峰谷抽稀。

`python tools/plot_smoke.py` 在有 Tcl/Tk 桌面的环境中验证弹窗、后台加载、局部重绘、关闭重开及 PNG 导出。
