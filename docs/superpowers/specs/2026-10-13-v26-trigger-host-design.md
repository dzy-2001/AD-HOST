# AD-HOST V26 上位机设计方案

日期：2026-10-13。目标版本：0.4.0。状态：设计完成，待用户审阅后实现。

## 1. 目标与依据

面向已升级 STM32/FPGA V26 固件的双通道采集设备，使用 Python 桌面上位机配置采样窗口、阈值触发和前后触发比例，可靠接收并保存大体积 ASCII HEX，显示状态并复用离线绘图。

用户明确要求：时间设置、采样点数设置、类似示波器的触发、电压/电流阈值比较、前后触发百分比、手动与自动模式，以及新建 GitHub 分支保存工作。

依据用户提供的《V26_协议指令与上位机开发说明.md》（2026-10-13），以及现有 AD-HOST 0.3.0 源码。该文件描述固件接口，不能代替固件源代码审查或硬件验证；其自述尚未完成 Keil 编译与上板验证。

保留已确认的电压公式 `(raw × 2 / 4096 − 1) × 6 V`；电流没有标定系数，继续显示 ADC 码。两通道均为 12 位无符号数。采样率固定 100 MSPS/通道。

## 2. 协议能否满足六项目标

| 目标 | V26 支持 | 主机处理 |
|---|---|---|
| 设置采样时间 | 支持，1–200 ms | CFG/ACQ 的 lenMode=0；整条记录包含前后触发 |
| 设置采样点数 | 支持，1–20,000,000 对 | lenMode=1；一对含电压、电流各一个样本 |
| 类似示波器的触发 | 支持单次阈值触发和手动触发 | ARM 后建立历史，等待条件或用户 FORCE |
| 电压、电流与阈值比较 | 支持 ≥、>、=、≤、< | 两路可分别使能；同时使能是逻辑 OR |
| 触发前后比例 | 支持 PRE=0–100 | 前 P=floor(N×PRE/100)，后 Q=N−P |
| 手动、自动模式 | 支持 MODE=0/1 | 手动按钮 FORCE；自动等条件，不发送 FORCE |

边界：没有上升沿/下降沿检测、迟滞、脉宽、绝对值比较、两通道 AND，也没有示波器 Auto 模式的超时强制触发。严格相等没有容差。每个 ARM 只产生一条记录，重复采集由主机逐条调度，传输期间不保证连续无死区采样。

PRE=100 的记录全部在触发之前，触发样本不在文件内。自动等待时间不限；200 ms 是记录窗口上限，不是等待或 TCP 传输期限。组间隔起点是上一组 RELEASE 完成，不是主机收完文件的时间。

## 3. 实现路线选择

1. **推荐：保留 Tkinter、NumPy、Matplotlib，重构协议调度，升级现有界面。** 复用已验证的文件解析与峰谷概览，重点解决串行交互和设备状态控制，交付独立 Windows 便携版。
2. 只给旧界面增加快捷指令按钮：修改较小，但旧版 SET 后立即 GET、任意手动发送和并发查询容易违反 V26 协议，不满足可靠自动采集要求。
3. 重写为其他 GUI 框架或网页：可扩展界面，但本次协议能力不依赖更换框架，会增加部署和验证工作。

推荐路线的默认设置：10 ms、前触发 30%、手动模式、单次记录；阈值使用 ADC 码输入。重复自动采集默认关闭，组间隔默认 1000 ms。所有默认值都通过完整配置明确下发，不依赖 FPGA 上电值。

## 4. 用户界面

主界面采用三个页签，避免把所有设置挤在一个长窗口中。

### 4.1 采集与触发

- 连接区：IP、端口、保存目录、连接/断开、固件版本与兼容性状态。
- 长度区：时间/点数二选一，整数输入；旁边预估每通道点数、总窗口、HEX 文件大小。
- 位置区：前触发百分比输入/滑块，同步显示后触发百分比和前后点数；PRE=100 有明确说明。
- 模式区：手动触发/自动阈值触发；自动模式至少启用一个通道。
- 两路阈值区：参与触发复选框、比较符下拉框、0–4095 ADC 码。电压可附只读的既有公式换算参考值，电流不显示 A。页面明确标注“两路为或关系；这不是边沿触发”。
- 操作区：应用配置（不启动）、准备采集、手动触发、取消采集、读取已有记录、丢弃已有记录。
- 重复区：仅自动模式可开启重复记录；设定组间隔；“停止后续记录”允许当前记录正常完成。取消当前记录使用独立按钮。
- 状态区：配置中、建立前触发历史、等待手动/条件触发、触发后采样、读取传输、写盘、组间隔、就绪、需处理异常。
- 进度区：预计/已收/已写字节、当前 MB/s、总用时、待写缓冲、成功记录数、文件路径。等待触发不显示虚假的百分比。

当前记录的配置在启动时冻结。运行中禁用配置修改，避免用户把“下一组设置”误认为“本组设置”。按钮是否可用同时由主机任务状态和设备状态决定，后台再次检查以防旧界面快照导致误操作。

### 4.2 波形与离线分析

保留独立绘图弹窗及文件选择；新增“打开最近记录”。读取同名 JSON 元数据后，以触发为 t=0：`t_ms=(i−ACTIVE_PRE)×1000/RATE`。显示触发原因、触发线、前后区域。PRE=100 时注明触发点在最后一个样本之后。

保留峰谷抽稀概览、缩放后重新选取原始点、范围选择与图片保存。图片保存当前视图；原始文件不变。V26 两路都检查 0–4095；旧文件兼容既有格式。没有元数据的历史文件从记录起点计时，明确说明触发位置未知，不能默认把首点当作触发点。

### 4.3 设备诊断

显示 VER/FST/TST/FREG 原始回复以及已解码状态、触发原因和错误位。查询也必须经过统一调度。保留受协议约束的单条 ASCII 指令发送入口：正文最多 127 字节，自动追加 CR；禁止多条拼接、任意二进制绕过调度以及 GET 中发送任何控制命令。

有状态影响的指令通过与图形按钮相同的调度路径执行。未知指令或无法跟踪的操作拒绝发送并说明原因。FINIT 和 CLEAR_EVENTS 作为诊断操作，不在正常等待或采集期间自动执行。

## 5. 命令流程与状态管理

### 5.1 连接和恢复

串行执行 VER → FST → TST，检查 STM32 V26、FPGA ID=ADFC/VER=0200、INIT=1/IERR=0 及文档给出的时钟值。设备不匹配时禁用采集并显示诊断，不悄悄套用 V3 协议。

已存在 BUSY/DONE/PENDING 时显示当前记录状态，不自动重 ARM、FINIT、ABORT 或 RELEASE。可由用户取消未完成记录、读取有效记录或丢弃已完成记录。重连不能从 TST 的 MODE/阈值推断正在运行记录的完整锁存配置；未知配置在元数据中明确标记未知，不能伪造。手动 FORCE 只在本机能确认本次锁存手动模式时提供。

### 5.2 配置与启动

应用配置：先检查可配置状态，发送 CFG 十字段，等待确认，再 TST 核对配置。不把部分写失败当作已回滚；失败后停止自动动作并查询实际配置。

准备采集：就绪检查 → CFG → TST 核对 → ARM → 等接受回复 → 保存已锁存配置 → 串行轮询 TST（默认 100 ms，上一条必须完成）。使用该显式流程便于确认配置与启动分离。ACQ 作为等价的协议操作支持，但其成功只表示 ARM 已接受。

手动模式：显示历史建立状态；满足 BUSY=1、DONE=0、ARMED=1、HISTORY_READY=1、TRIGGERED=0、无错误且本次手动时，启用“手动触发”。用户点击后发 FORCE，继续等完成。

自动模式：ARM 后持续等条件；不自动 FORCE，不因 READY=0 就报错或重启。

### 5.3 完成与读取

GET 门槛为 `(STATUS & 0x008C)==0x008C`、错误掩码 `0x1810` 为零、PENDING=1、控制空闲。保存 GET 前的完整 TST 及本次配置。

核对 1≤SAMPLES≤20,000,000、TOTAL=SAMPLES×4、HEX_CHARS=SAMPLES×8、BLOCKS=ceil(TOTAL/8192)、0≤ACTIVE_PRE≤SAMPLES、RATE=100000000。本机启动的记录同时与锁存长度/前触发点数交叉验证。跨域状态短暂不一致时重新查询；持续矛盾则停止，不能猜测数据长度。

发送 GET 后停止所有 TST/FST/VER/控制命令。接收恰好 HEX_CHARS 个正文字符和三字节 CR LF *；GET 没有前置成功确认。TCP 分片、半字跨包、标志分片及同包正文/尾标志均正确处理，剩余字节留在协议缓冲。

严格验证正文为 0–9/A–F、每组 8 字符、两路高 4 位为零；校验总对数、尾标志及写盘结果后才标记成功。GET 中途问号、非法字符、断线或无进度超时均为失败，不能生成成功文件或继续下一组。

### 5.4 重复自动记录

每条完整落盘后读取 TST，等 READY、无错误、PENDING=0、GAP_LEFT_MS=0，再 ARM 沿用已确认配置。PC 不独立猜测 RELEASE 时刻。手动模式不使用自动组间隔。

停止后续记录：不再 ARM；当前采集/传输正常完成。取消当前记录：按下一节处理，同时关闭重复记录。

协议的示例完成快照遗漏 GAP_MS/GAP_LEFT_MS，而字段表要求存在。实现不把缺失 GAP_LEFT_MS 当 0；缺字段时禁用重复自动记录并提示固件接口待核对。单次读取按必要元数据判断。

## 6. 线程、文件与异常

采用主 GUI 线程、唯一 Socket/协议调度线程、独立写盘线程；离线文件解析继续使用独立后台任务。唯一协议线程收发所有命令，始终最多一个请求等待回复；GUI 只提交操作请求和读取快照。

接收使用有界缓冲队列：默认 64 MiB，可选 16/64/256 MiB，单位与实际分配一致。接收块最高 1 MiB，Socket 请求缓冲 32 MiB。大数据不拼接进 GUI，不逐字符写日志，使用批量校验。写盘错误必须及时反馈，不能使接收线程永久等待满队列。

每组独立 HEX + JSON，记录：固件版本、启动时已确认配置、GET 前 TST、真实 RATE/ACTIVE_PRE/REASON、期望/接收/写入字节、错误、时间、成功状态。完成判定包括文件 flush/fsync/close 和元数据写入；失败或中断的文件保留为 `.partial.hex` 并标明未完成。不能将失败文件自动作为正常波形打开。

普通命令回复默认 5 秒超时，GET 默认 30 秒无接收进度超时（可调整），触发等待无限制且可取消。持续有进度的 GET 不受固定总时间限制，也不使用采样窗口长度作为网络超时。

ARM/FORCE/ACQ 回复超时后禁止盲目重发。由于协议没有请求 ID，超时后的迟到回包不能可靠配对：停止调度，关闭旧连接，重连并预检实际状态后再由用户继续。不能把下一次 TST 的回复当成上一条命令确认。

取消：BUSY 且未 DONE 时 ABORT；若返回失败，重新查询，可能已完成，应在 RELEASE 门槛满足时丢弃。DONE 时 RELEASE 必须满足 BUSY=0、BLOCK_READY=0，且 READ_READY/STREAM_DONE/OVERFLOW 至少一个有效。GET 中取消只关闭连接，不发送 ABORT。重连后等待设备清理并检查状态。

## 7. 验证与验收

协议模拟器覆盖 V26 的命令/状态/长度及失败路径，并验证没有在握手/GET 中插入其他命令。它用于验证主机，不代表 FPGA RTL 或 STM32 固件已上板通过。

- 参数：全部范围边界、时间/点数互斥、自动模式 ENABLE=0 拒绝、比较编码、127 字节和真实 CR。
- 回包：大小端、十六进制状态与十进制计数、乱序字段、FST 的 SET 内嵌逗号、缺字段、TCP 拆包/粘包、尾标志分片。
- 流程：手动历史未就绪不能 FORCE、自动不 FORCE、ARM 确认不代表 DONE、GET 期间不轮询、重复组等待真实 GAP_LEFT_MS。
- 恢复：启动回复丢失不重试、配置失败查实际值、取消与 DONE 竞争、溢出不 GET、接收中断、写盘失败、重连已有记录。
- 波形：PRE=0/30/100、SAMPLES=1、触发相对时间、两通道范围检查、旧文件无元数据行为、放大保留细节。
- 性能：160 MB 最大协议记录，通过模拟接收检查字节完全一致、缓冲有界、成功状态在文件关闭之后出现。
- Windows GUI：配置输入、状态/按钮、手动触发、取消、最近记录、绘图弹窗、导出和退出。CI 通过后生成可直接运行的便携版。

验收口径：六项用户目标均可操作，设备回读决定动作与触发坐标，异常不会被标为成功；主机模拟验证与真实设备联调分别报告。
