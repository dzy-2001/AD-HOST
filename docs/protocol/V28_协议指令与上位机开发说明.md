# V28 STM32 对接与上位机指令说明

适用工程：`ETHEL_STM32F429IGT6_FPGA_ENET_V28`；FPGA ID `0xADFC`、RTL VERSION **`0x0201`**。STM32 `VER` 为 `V1.0.15 (V28)`。本版基于 V27 正常程序，不是 PB0 静态常亮诊断版。PB0_RUN_LED 的正确电路为 3.3 V → R3 → LED1 → PB0（低电平亮）；曾不亮的实物原因是 LED 反焊，程序维持原 TIM3_CH3 呼吸实现。

## 连接与回复

默认 TCP 目标为 `192.168.3.178:11235`。发送每一行指令后附真实 CR 字节 `0x0D`，等其回复完整再发下一行。普通成功回复 `\r\n*`；失败 `\r\n?`。文本查询返回字段正文后接 `\r\n*`。GET 直接连续返回 ASCII HEX 数据，末尾才返回 `\r\n*`，期间不要发送其他命令。

先发送 `VER`、`FST`、`TST`。期望：
- VER：`V1.0.15 (V28)\r\n*`。
- FST：`ID:ADFC,VER:0201,INIT:1,IERR:0`；HCLK 约 168000000、SDCLK 约 56000000。
- 启动前 TST 的 `(STATUS & 0x2061) == 0x2061`、`(STATUS & 0x1810) == 0`，`PENDING:0`。

## 逗号配置指令

推荐发送 **11 个无符号十进制参数**：

```text
CFG lenMode,length,pre,mode,vth,vcmp,ith,icmp,enable,gapMs,rateMsps
ACQ lenMode,length,pre,mode,vth,vcmp,ith,icmp,enable,gapMs,rateMsps
```

`CFG` 写配置并读回，成功后回复 `*`，不启动采集。`ACQ` 配置后发 ARM，成功 `*` 只代表 FPGA 接受 ARM，仍需等触发与 DONE。原 V27 **10 参数**形式继续兼容，省略最后的 `rateMsps` 时明确设置为 **100**，不会沿用先前的低保存速率。参数缺失、负数、尾随字符、越界在写寄存器前拒绝；FMC 写入后若读回失败，可能出现部分参数已写入，请 TST 核对。

| 参数 | 取值 | 含义 |
|---|---:|---|
| lenMode | 0 或 1 | 0=时间模式；1=总 A/B 对数模式 |
| length | 时间模式 1～200；点数模式 1～20000000 | 单位分别是 ms 和 A/B 对 |
| pre | 0～100 | 总记录内前触发比例，`P=floor(N×pre/100)` |
| mode | 0 或 1 | 手动 FORCE 或自动阈值触发 |
| vth / ith | 0～4095 | A/B 校正后 12 位 ADC 码；尚无 V/A 标定时直接用码值 |
| vcmp / icmp | 0～4 | 0≥、1>、2=、3≤、4<；无符号严格比较 |
| enable | 0～3 | bit0=A 电压、bit1=B 电流；自动模式不可为 0 |
| gapMs | 0～600000 | 自动组之间至少等待的 ms 数，从上一组 RELEASE 完成起算；STM32 实现 |
| rateMsps | 1～100 | 保存速率 R，单位 MSPS；原始 ADC 时钟仍为 100 MHz |

**时间模式**：`N = length × rateMsps × 1000`；例如 2 ms、5 MSPS，N=10000 对、40000 原始字节、80000 个 HEX 字符。写 RATE 时 FPGA 会在当前时间模式重算 N。**点数模式**：`N = length`；改 RATE 不改变 N，整条记录对应的时间会变化。单组最多 20000000 对。

触发仍按原始 100 MHz ADC 数据检测；命中后的**下一个保存点**是前后触发边界，因此边界保存点自身可能不满足比较条件。pre=0 边界为第 0 对；0<pre<100 为第 P 对；pre=100 的 N 对均为前触发，记录不包含边界点。两路为 OR，同一拍都满足时原因位可同时出现。手动 FORCE 不精确对应电脑发送时刻。

## 单参数与控制

| 命令 | 参数 / 条件 | 成功含义 |
|---|---|---|
| `RATE n` | 1～100 MSPS | `0x0046` 写入并读回；配置下一条记录 |
| `TIME n` | 1～200 ms | 写 TIME_MS，按当前 RATE 重算 N，切时间模式 |
| `SAMPLES n` | 1～20000000 对 | 低/高半字都写完，切点数模式 |
| `PRE n` / `MODE n` | 0～100 / 0～1 | 配置前触发比例 / 手动或自动 |
| `VTH n` / `ITH n` | 0～4095 | A/B ADC 阈值码 |
| `VCMP n` / `ICMP n` | 0～4 | A/B 比较方式 |
| `ENABLE n` | 0～3 | 通道使能位 |
| `ARM` | READY 且初始位正常；自动模式 ENABLE≠0 | 接受一次采集，先建立历史 |
| `FORCE` | 手动且 ARMED=1、HISTORY_READY=1 | 手动触发已到达 ADC 域 |
| `ABORT` | BUSY 且未 DONE | 取消正在准备/等待/采集的记录 |
| `RELEASE` | DONE、BUSY=0、无 BLOCK_READY | 主动丢弃未 GET 的记录 |
| `CLEAR_EVENTS` | 无 GET/控制握手 | 清旧事件，不取消记录 |
| `GET` | DONE、VALID、READ_READY 且记录未被消费 | 发送完成记录并自动 RELEASE |
| `SET n,0` / `SET n,1` | n=1～200 | 兼容旧命令，先恢复 RATE=100；1 另设手动/PRE=0 并 START |
| `VER` / `FST` / `FREG` / `TST` | 查询 | 软件版本 / 初始化诊断 / FMC 联调 / 触发状态 |

RATE 和其余寄存器写入在已有记录活动期间只影响**下一条**；ARM/START 接受时 FPGA 锁存整套配置。单参数配置时若需要确认总点数，TST 的 `CFG_SAMPLES` 是点数寄存器读值；时间模式下按 TIME 与 CFG_RATE_MSPS 计算 N。为了避免配置顺序误读，建议用完整的 CFG 或 ACQ。

## TST 期望回读

TST 的 `STATUS`、`EVENTS`、`TRIGGER` 为十六进制，其余数值字段为十进制。新增字段：

| 字段 | 含义 |
|---|---|
| `CFG_RATE_MSPS` | 0x0046 下一组保存速率，默认 100 |
| `ACTIVE_RATE_MSPS` | 0x0048 当前已锁存组的保存速率 |
| `TRIGGER_DELAY_TICKS` | 0x004A FPGA 提供的原始触发时序值 |
| `TRIGGER_PHASE` | 0x004C FPGA 提供的原始相位值 |
| `RATE` | 旧字段继续表示 0x003C/3E **原始 ADC 时钟 Hz**，正常为 100000000；不是保存速率 |
| `ACTIVE_PRE` | 锁存的触发边界索引 P |
| `SAMPLES` / `TOTAL` / `BLOCKS` | DONE/VALID 后的实际 A/B 对数、字节数、`ceil(TOTAL/8192)` |
| `HEX_CHARS` | GET 的 ASCII HEX 字符总数，`TOTAL×2` |
| `GAP_MS` / `GAP_LEFT_MS` | STM32 配置的自动组间隔 / 尚需等待时间 |

`TRIGGER_DELAY_TICKS` 和 `TRIGGER_PHASE` 此版只透传寄存器原始整数；附件提到的《采样率扩展协议.md》未随文件提供，不能据此杜撰精确物理触发时间换算。DONE 后读这两个字段用于后续上位机时间轴对接。

状态判断：
- 启动前：`STATUS & 0x2061 == 0x2061`，错误 `STATUS & 0x1810 == 0`。
- 自动等待：READY=0、BUSY=1 是正常状态；**没有固定采集超时**。
- 手动触发：TST `ARMED:1,HISTORY_READY:1,TRIGGERED:0` 后 FORCE。
- 可 GET：`STATUS & 0x008C == 0x008C`，错误掩码为 0，PENDING=1。
- 若 OVERFLOW=1、DONE=1、VALID=0，不能 GET；读端空闲时 RELEASE 后重试。
- ABORT 后 READY=1、VALID=0、PENDING=0；若已经 DONE，请改用 RELEASE。

## GET 数据格式和收包

STM32 对每个 FMC 16 位样本输出 **4 个大写 ASCII HEX 字符**，顺序 A0、B0、A1、B1……。例如两个样本半字 `0x0123`、`0x0456` 输出 `01230456`；这是字符序列，不是二进制大小端字节流。先按 TST 的 `HEX_CHARS` **准确收满**，再读结束符 `\r\n*`；数据字符以外的 TCP 分包边界与 FPGA 8 KiB 块无关。

固件使用 READ_NEXT → 等 BLOCK_READY → 校验编号/偏移/长度/末块 → 复制整个 8 KiB 块到 STM32 独立缓冲 → ACK 接受 → 发送 HEX。末块 ACK 后等 STREAM_DONE，再 RELEASE。ACK 释放的是 FPGA 块缓存，不是上位机 TCP 接收确认。GET 中断线时固件排空、ACK 并 RELEASE，不把旧流发给新连接。若流中途失败，不能把已收到前缀当成完整记录。

自动间隔不会让 FPGA 自动重复采集：每组仍需上位机发送一次 ACQ 或 ARM。上位机轮询 TST 时让网口服务运行；GET 正在传波形期间不要交错发送 TST。

## 典型命令

以下每一行单独发送，附真实 CR，并等待完整回复：

```text
VER
FST
TST
ACQ 0,2,30,1,2500,0,1500,4,3,1000,5
TST
GET
```

这组为 2 ms、保存 5 MSPS、10000 对、前触发 3000 对；自动触发 A≥2500 或 B<1500；GET 预期 80000 个 HEX 字符后 `\r\n*`。TST 等 DONE/VALID/READ_READY 后才能 GET；完成后等待 `GAP_LEFT_MS:0`，再 ARM/ACQ 下一组。手动用同样的 CFG（MODE=0）→ ARM → TST 等 HISTORY_READY → FORCE → TST 等 DONE → GET。
