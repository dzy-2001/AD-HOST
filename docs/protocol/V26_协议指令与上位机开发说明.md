# V26 协议指令与上位机开发说明

版本：2026-10-13。适用工程：`ETHEL_STM32F429IGT6_FPGA_ENET_V26`。

本文件依据已交付 V26 的 `fpga.c`、`fpga.h`、`fpga_trigger_v2.h`、`sendtcp.c` 和命令解析代码整理。
下文区分正式 FPGA 协议与当前 V26 TCP 接口的实际行为。示例回读是字段解释示例，不是上板实测日志。
已交付工程做过软件模拟测试，尚未完成 Keil 编译和上板验证。

## 0. V26 推荐的合并指令与组间隔

V26 在 V25 的 STM32 TCP 指令上新增以下两条。FPGA 寄存器协议仍为 `0x0200`，无需更改 FPGA RTL。旧的单参数命令继续可用。

```text
CFG lenMode,length,pre,mode,vth,vcmp,ith,icmp,enable,gapMs
ACQ lenMode,length,pre,mode,vth,vcmp,ith,icmp,enable,gapMs
```

十个字段全部为**无符号十进制整数**，必须齐全，按顺序用英文半角逗号隔开。命令前缀和参数之间留一个空格；逗号前后可有空格/Tab。末尾发送真实 CR (`0x0D`)。非法值、缺项、多项、负数、溢出或尾部字符返回 `\r\n?`，解析拒绝时不会写入任何 FPGA 配置。写寄存器中途若读回失败，硬件可能已部分更新，应先 TST 核对。

| 顺序 | 字段 | 允许值 | 含义 |
|---:|---|---|---|
| 1 | lenMode | 0 / 1 | 0：时间模式；1：对数模式 |
| 2 | length | 时间模式 1～200；对数模式 1～20000000 | 时间单位 ms；点数单位 A/B 对。总记录窗口含前触发与后触发 |
| 3 | pre | 0～100 | 前触发百分比；P=floor(N×pre/100) |
| 4 | mode | 0 / 1 | 0 手动（ARM 后 FORCE）；1 自动（满足任一使能条件触发一次） |
| 5 | vth | 0～4095 | A 路电压 ADC 阈值码 |
| 6 | vcmp | 0～4 | A 路比较编码：0≥、1>、2=、3≤、4< |
| 7 | ith | 0～4095 | B 路电流 ADC 阈值码 |
| 8 | icmp | 0～4 | B 路比较编码，同上 |
| 9 | enable | 0～3 | bit0 A，bit1 B；自动模式不能为 0，手动可为 0 |
| 10 | gapMs | 0～600000 | 两条**自动**记录之间的最短间隔，毫秒；0 关闭限制。推荐先试 1000，再按业务调整 |

`CFG` 写入并核对配置，返回 `\r\n*` 表示这批配置已读回相符，**不会 ARM**。`ACQ` 写入相同配置后立即启动 ARM；它的 `*` 只表示 FPGA 已接受 ARM，不表示触发、DONE 或 GET 完成。先 `CFG` 一次、后续单独 `ARM` 可减少重复传参；若下一组要改变参数，直接使用 `ACQ`。未配置时不应仅依赖 FPGA 复位默认值。

例如发送 `ACQ 1,100000,30,1,2500,0,1500,4,3,1000\r`。等待 `*`，用 `TST` 轮询至 DONE/VALID/READ_READY，再 `GET`；完整接收波形及结尾 `\r\n*` 后，`TST` 查看 `GAP_LEFT_MS`。待其为 0，下一条 `ARM`（沿用已设置配置）或 `ACQ ...`（重配）才会被接受。过早发送会得到 `\r\n?`，`TST` 的 `GAP_LEFT_MS` 仍提供剩余时间。

**间隔的起点是上一条自动记录 RELEASE 完成、FPGA 回到 READY 的时刻。** 正常 GET 会自行 RELEASE；DONE 后主动 `RELEASE` 丢弃记录也会计入间隔。ABORT 不开启新间隔。该限制只在 STM32 收到下一次自动 ARM/ACQ 时检查，不改变 100 MSPS、记录点数或 FPGA 触发比较；手动记录不受限制。`gapMs` 是当前 STM32 设置：新 `CFG/ACQ` 可以更新它，单参数设置不改变它，`FINIT`/重新初始化将它清零。首次上电没有上一组，立即允许 ARM。

FPGA V2 每次 ARM **只生成一条记录**：即使阈值始终成立，也不会自动连续建组。上位机必须逐组执行“ARM/ACQ → 等 DONE → GET/RELEASE → 等 GAP_LEFT_MS=0 → 再 ARM/ACQ”。这条间隔由 STM32 的毫秒时基测量，收到 ACQ 的时刻、实际触发时刻和 TCP 接收端完成时间都不是间隔起点；主机如果需要更严格的触发时间或保证断电后仍保留组间隔，需要扩展 RTL/持久时钟协议。

## 1. 连接、命令与回包约定

| 项目 | 约定 |
|---|---|
| 连接方式 | TCP，板卡为服务器，上位机为客户端 |
| 默认板卡 IP | `192.168.3.178` |
| TCP 端口 | `11235` |
| STM32 软件版本 | `VER` 返回 `V1.0.13 (V26)` |
| FPGA ID / VERSION | `0xADFC` / `0x0200`；FST 中显示 `ID:ADFC,VER:0200` |
| 命令文本 | ASCII，大写命令名，区分大小写 |
| 命令结束 | 必须发送真实回车字节 `0x0D`，即 `\r` |
| 换行 | `\n` 被忽略；可以用 CRLF，但单独 LF 不执行命令 |
| 参数 | 无符号十进制整数，不使用 `0x`、负数、小数、V/A 单位后缀 |
| 执行顺序 | 一次一条命令，收到完整回复再发送下一条 |
| 命令长度 | 当前命令缓冲可容纳 127 字节正文；使用本文件中的短命令 |
| 成功标志 | `\r\n*`，实际字节 `0D 0A 2A` |
| 失败标志 | `\r\n?`，实际字节 `0D 0A 3F` |

发送 `TIME 1\r` 的实际字节为 `54 49 4D 45 20 31 0D`，不能发送字面字符“反斜杠+r”。
配置命令允许参数前后空格/Tab。无参数命令使用精确正文，例如 `ARM\r`，不要附加空格或注释。

### 1.1 三类回包

| 类型 | 命令 | 回复结构 |
|---|---|---|
| 简单确认 | CFG、ACQ、TIME、SAMPLES、PRE、MODE、VTH、ITH、VCMP、ICMP、ENABLE、SET、ARM、FORCE、ABORT、RELEASE、CLEAR_EVENTS、FINIT | 成功 `\r\n*`；失败 `\r\n?` |
| 文本查询 | VER、TST、FST、FREG | 文本正文后接 `\r\n*`；查询失败可能只有 `\r\n?` |
| 波形读取 | GET | 成功为 HEX 波形正文后接 `\r\n*`；GET 不先返回独立成功确认 |

成功的含义随命令不同，不能统一理解成“采集完成”。ARM 成功只说明接受准备采集；FORCE 成功说明观察到触发。
TCP 是字节流：一条回复可被拆成多个接收包，多条回复也可能处于同一接收包。保留未消费的接收字节。

### 1.2 串行发送限制

V26 在控制握手期间忽略额外送入 FPGA 命令处理器的命令；GET 活动期间忽略所有额外命令，包括查询、ABORT 和 VER。
被忽略的命令不会排队，也不会保证返回 `?`。上位机必须自行串行调度，不使用命令流水线。
VER 的分派路径位于 FPGA 命令处理器之前，也不要在控制握手期间插入 VER，以免交错回复。

自动等待触发不是控制握手：ARM 的回复已经收到、GET 尚未开始时，可以发送 TST、下一次配置和 ABORT。
GET 期间禁止定时器继续轮询 TST/FST；收完波形或断线处理完毕后再恢复查询。

## 2. 采集对象、长度与触发位置

A 路为电压，外部电路从 JP1/JP3 二选一接入；B 路为电流，从 JP2/JP4 二选一接入。
每通道固定 100 MSPS，即相邻采样对间隔 10 ns。一个“点”是一对同时采到的 A/B。
每路为校正后的 12 位无符号码，放在 16 位半字低 12 位，高 4 位为 0。每对原始数据为 4 字节。

```text
时间模式：N = TIME_MS × 100000
点数模式：N = SAMPLES
前触发：  P = floor(N × PRE / 100)
后触发：  Q = N − P
原始字节：TOTAL = N × 4
波形字符：HEX_CHARS = N × 8 = TOTAL × 2
读块数量：BLOCKS = ceil(TOTAL / 8192)
```

TIME/SAMPLES 最后一次成功写入的长度设置生效，不能将两种长度相加。时间是整条记录长度，不是额外后触发时长。

| 总记录时间 | 总对数 N | 原始字节 TOTAL | TCP 波形字符数 |
|---|---:|---:|---:|
| 1 ms | 100000 | 400000 | 800000 |
| 10 ms | 1000000 | 4000000 | 8000000 |
| 100 ms | 10000000 | 40000000 | 80000000 |
| 200 ms | 20000000 | 80000000 | 160000000 |

200 ms 是最大记录窗口，自动/手动等待触发没有固定期限；TCP 传输时间也不受 200 ms 限制。
点数模式可以小于 1 ms，例如 SAMPLES=1 只记录一对。

| PRE | 数据含义与触发位置（索引从 0 开始） |
|---|---|
| 0 | 无前触发历史；触发样本为第 0 对 |
| 1～99 | 第 0～P−1 对为触发前，第 P 对是触发样本，属于后触发部分 |
| 100 | 返回触发前 N 对，不含触发样本；触发位置为 N，在记录末尾之后 |

显示波形时，采样对 i 相对于触发的时间为 `(i−ACTIVE_PRE)/100000000` 秒。
优先使用本次 `ACTIVE_PRE`，不要用已经可能被改写的 PRE 重新计算当前触发位置。

## 3. 参数配置命令

本节单参数配置命令与 `CFG` 只设置下一条记录，不开始采集；`ACQ` 则配置并 ARM。成功表示已写入并通过当前 V26 的寄存器读回校验。
ARM/START 接受时锁存配置；已运行的记录不会因后续配置写入而改变。

| 指令语法 | 参数范围 | FPGA 复位默认值/说明 | 成功回包 |
|---|---|---|---|
| `TIME n` | 1～200 ms | 本协议未指定初始时间；每次任务明确配置长度 | `\r\n*` |
| `SAMPLES n` | 1～20000000 对 | 本协议未指定初始点数；完整写入低/高半字 | `\r\n*` |
| `PRE n` | 0～100 % | 0 | `\r\n*` |
| `MODE n` | 0 手动，1 自动 | 0 | `\r\n*` |
| `VTH n` | 0～4095 ADC 码 | 4095，A 路电压阈值 | `\r\n*` |
| `ITH n` | 0～4095 ADC 码 | 4095，B 路电流阈值 | `\r\n*` |
| `VCMP n` | 0～4 | 0，A 路比较方式 | `\r\n*` |
| `ICMP n` | 0～4 | 0，B 路比较方式 | `\r\n*` |
| `ENABLE n` | 0～3 | 3，两路使能 | `\r\n*` |

任一命令失败返回 `\r\n?`。失败后先 TST 核对实际配置，不能假定所有配置都已回滚。
VTH/ITH 不是伏特/安培。当前没有 V/A 标定指令；上位机应使用 ADC 码调试。
以后换算物理量时必须使用实际标定；负斜率模拟通道需要反转比较方向。

### 3.1 比较方式

| VCMP/ICMP | 条件 | 说明 |
|---:|---|---|
| 0 | 当前码 ≥ 阈值 | 大于等于 |
| 1 | 当前码 > 阈值 | 严格大于 |
| 2 | 当前码 = 阈值 | 严格相等，无容差 |
| 3 | 当前码 ≤ 阈值 | 小于等于 |
| 4 | 当前码 < 阈值 | 严格小于 |

比较对象是经过原工程输入取反校正后的当前存储码。不是有符号比较、绝对值比较或边沿检测，没有迟滞。

### 3.2 通道使能

| ENABLE | 电压 A | 电流 B | 自动模式能否 ARM |
|---:|---|---|---|
| 0 | 禁用 | 禁用 | 不能，会拒绝 |
| 1 | 使能 | 禁用 | 能 |
| 2 | 禁用 | 使能 | 能 |
| 3 | 使能 | 使能 | 能，任一路满足即触发，两路逻辑 OR |

手动模式忽略两路阈值结果，ENABLE=0 也可手动 ARM。
ENABLE 只控制触发参与条件，不改变两路同时记录的 A/B 数据结构。
单独 `ENABLE 0` 可以成功配置；如果随后 MODE=1，ARM 将失败。这是组合配置检查。

## 4. 采集控制命令与期望反馈

### 4.1 ARM：准备采集并等待触发

前提：FMC 初始化通过，READY/CFG_DONE/CALIB/MODE_VALID=1，错误位 4/11/12=0，PENDING=0，无活动 GET/控制握手。

ARM 接受后 FPGA 锁存配置、开始准备采集/建立历史。手动模式历史就绪后等待 FORCE；自动模式历史就绪后持续比较。
历史不足时满足条件不会被锁存；历史足够后如果当前值仍满足，会触发。自动 ARM 可能很快完成记录。

成功 `\r\n*`：STM32 观察到 EVENTS bit0（ARM/START_ACCEPTED）。不是 DONE 确认。
失败 `\r\n?`：本地条件不满足、FPGA 拒绝或控制反馈超时。接受反馈超时不等于 FPGA 肯定未执行，必须先查询状态。

例：TIME=100、PRE=30，建立约 30 ms 历史后，继续覆盖历史并等待。5 秒后触发，保留触发前最近 30 ms 加后 70 ms。

### 4.2 FORCE：触发本次手动记录

前提：本次已 ARM，锁存 MODE=0，BUSY=1、DONE=0、ARMED=1、HISTORY_READY=1、TRIGGERED=0，且无错误。

FORCE 不改变 TIME/SAMPLES/PRE，不重新 ARM。它经跨时钟握手到 ADC 域，因此不是电脑发出命令的精确时刻。
成功 `\r\n*`：观察到 TRIGGERED=1；仍需等 DONE/VALID/READ_READY。
FORCE 无独立成功事件，不能要求 EVENTS bit0 因 FORCE 重新置位。
自动模式、没有 ARM、历史不足、已经触发都会拒绝或不满足发送条件。

等待期间即使将下一次 MODE 改为 1，本次手动记录仍可 FORCE；判断使用本次锁存模式。

### 4.3 ABORT：取消尚未完成的 FPGA 采集

前提：BUSY=1 且 DONE=0。可取消准备阶段、历史建立、等待 FORCE、等待自动条件，以及已触发但尚未完成的采样/收尾。

成功 `\r\n*`：已观察到 READY=1、BUSY=0、VALID=0，并且 ABORTED=1。取消和内部排空需要时间，不是写入后立即结束。
主要价值是取消无限期的触发等待；记录最大 200 ms 不代表等待也只有 200 ms。
已 DONE 应使用 RELEASE。GET 期间额外命令被忽略，不能用 ABORT 终止活动 GET；上位机若必须停止接收，可关闭连接。

### 4.4 RELEASE：丢弃完成记录

前提：DONE=1、BUSY=0、BLOCK_READY=0、无活动 GET。当前 V26 还要求 READ_READY/STREAM_DONE/OVERFLOW 至少一个为 1，防止读请求尚在进行时释放。

成功 `\r\n*`：READY=1、BUSY=0、VALID=0，PENDING 清零。
未 GET 的完成记录可主动释放；溢出导致 DONE=1、VALID=0 的记录也应在读端空闲时 RELEASE。
正常 GET 自动 RELEASE，不需要上位机额外发送。块占用期间不能通过 RELEASE 强行复位读端。

### 4.5 CLEAR_EVENTS：清事件和本地访问错误

一次写 CLEAR_EVENTS，再等待已知事件位清零，成功返回 `\r\n*`。
不重新采集、不清记录、不等于 ABORT，也不能代替 RELEASE 清除溢出记录。
V26 在 ARM/START/FORCE/ABORT/RELEASE 和内部读块/ACK 握手中自行清旧事件，上位机不必每一步再重复清除。
不要循环连续发送 CLEAR_EVENTS 等待其他命令完成，这会清掉需要观察的事件。

### 4.6 SET：旧立即采集兼容命令

| 命令 | 行为 | 成功含义 |
|---|---|---|
| `SET n,0` | n=1～200，更新 TIME 并切换时间模式；不改 MODE/PRE，不启动 | 时间配置读回正确 |
| `SET n,1` | 明确写 MODE=0、PRE=0、TIME=n，然后发 START=1 | FPGA 接受 START |

可以使用 `SET 100, 1`，但建议上位机统一输出 `SET 100,1`。
**不要先配置自动模式或前触发比例，再用 SET n,1 启动：它会覆盖 MODE/PRE。触发采集统一使用 ARM。**
FORCE 类似“触发按钮”，SET n,1 是“配置长度并立即启动一条无前触发记录”，不能互换。

### 4.7 GET：读取已冻结的完成记录

前提：PENDING=1、DONE=1、VALID=1、READ_READY=1、错误位为 0、TCP 已连接且没有活动传输。
当前 V26 不接受“先 GET 再等触发”：记录未完成立即返回 `\r\n?`。
GET 时刻不会启动新采样。读取内容是此前已完成并冻结的记录。

GET 成功不先回复 `*`，直接发送波形。接收规则见第 7 节。成功完成后 FPGA 记录被自动释放。
一条记录正常 GET 一次；再次 GET 返回失败，需要重新 ARM/START。

## 5. TST：回读格式、字段与状态判断

### 5.1 实际字段集合和数值进制

发送 `TST\r`。成功回复由以下字段组成，字段间逗号分隔，最后 `\r\n*`：

```text
STATUS,EVENTS,TRIGGER,ARMED,HISTORY_READY,TRIGGERED,ABORTED,REASON,CTRL,PENDING,
LENMODE,TIME,CFG_SAMPLES,PRE,MODE,VTH,VCMP,ITH,ICMP,ENABLE,
ACTIVE_PRE,RATE,SAMPLES,TOTAL,BLOCKS,DDR_WRITE_BURSTS,BURSTS_STABLE,HEX_CHARS,GAP_MS,GAP_LEFT_MS
```

实际形式为 `字段名:值`；以上只是字段列表，不是发送命令或完整回包。
STATUS/EVENTS/TRIGGER 为四位十六进制文本，不带 `0x`。其余均为十进制。
TST 不包含 FPGA ID/VERSION/INIT；首次连接应先 FST 核对这些值。

| 字段 | 含义与使用方法 |
|---|---|
| STATUS | 完整 FPGA 状态位，按十六进制解析，位表见 5.2 |
| EVENTS | 命令接受/拒绝事件，按十六进制解析，位表见 5.4 |
| TRIGGER | 完整触发位图，按十六进制解析，位表见 5.3 |
| ARMED | TRIGGER bit0，ADC 已开始本次采样且尚未触发；准备阶段可能还是 0 |
| HISTORY_READY | TRIGGER bit1，前触发历史足够；发送手动 FORCE 前检查 |
| TRIGGERED | TRIGGER bit2，本次已触发 |
| ABORTED | TRIGGER bit4，本次被取消；下次接受 ARM/START 时清除 |
| REASON | TRIGGER bits5～7 右移 5 后的组合值；当前 V26 在 DONE 前返回 0 |
| CTRL | STM32 握手阶段：0 空闲、1 等清事件、2 等控制结果；握手中 TST 通常被忽略，正常查询应为 0 |
| PENDING | STM32 记录占用标记，准备/等待/完成未释放时为 1；接受反馈丢失也可能保留 1，不能单独当 DONE |
| LENMODE | 0 时间设置，1 点数设置 |
| TIME | 配置时间毫秒；点数模式下为 0 |
| CFG_SAMPLES | 下一次配置总 A/B 对数 |
| PRE | 下一次配置前触发百分比 |
| MODE | 下一次配置手动/自动模式，不一定是本次锁存模式 |
| VTH / ITH | 下一次配置的 A/B ADC 阈值码 |
| VCMP / ICMP | 下一次配置的 A/B 比较编码 |
| ENABLE | 下一次配置的通道使能位图 |
| ACTIVE_PRE | 本次锁存配置计算的 P；DONE 后是零起始触发位置，PRE=100 时为 N |
| RATE | 固定 100000000 Hz；不是 SDCLK=56000000 Hz |
| SAMPLES | 仅 DONE 且 VALID 后返回实际记录对数，否则 0 |
| TOTAL | 仅 DONE 且 VALID 后返回有效原始字节数，否则 0 |
| BLOCKS | 根据 TOTAL 计算的总 GET 块数，无有效记录时 0 |
| DDR_WRITE_BURSTS | 32 字节 DDR 写突发累计计数，含环形覆盖，32 位回绕，不是 GET 块数 |
| BURSTS_STABLE | DDR 计数高—低—高复读是否一致；0 时丢弃该次 DDR 计数值，重读 |
| HEX_CHARS | TOTAL×2，是 GET 波形正文的 ASCII 字节数，不含末尾三字节标志 |
| GAP_MS | STM32 当前自动组间隔设定，毫秒；不是 FPGA 寄存器 |
| GAP_LEFT_MS | 从上一条自动记录 RELEASE 完成到允许下一次自动 ARM 的剩余毫秒数；0 可尝试新 ARM，仍须满足 READY 等条件 |

ARM/START 配置锁存后，上位机也应保存本次配置。V26 没有单独回读“本次锁存的所有阈值/模式”的字段。
配置准备/活动阶段的 ACTIVE_PRE 可能短暂滞后；DONE 后用于当前记录。不要要求所有状态寄存器同一时刻更新。

### 5.2 STATUS 位表

| bit | 掩码 | 名称 | 含义 |
|---:|---|---|---|
| 0 | 0x0001 | READY | 可以准备下一次采集 |
| 1 | 0x0002 | BUSY | 准备、等待触发、采样或收尾中 |
| 2 | 0x0004 | DONE | 记录完成；不是末块标志 |
| 3 | 0x0008 | VALID | 记录有效 |
| 4 | 0x0010 | OVERFLOW | 采集溢出；DONE 但 VALID=0 时不能 GET |
| 5 | 0x0020 | CFG_DONE | FPGA 配置完成 |
| 6 | 0x0040 | CALIB | DDR 校准状态满足启动要求 |
| 7 | 0x0080 | READ_READY | 读端可请求下一块 |
| 8 | 0x0100 | BLOCK_READY | 当前块缓存就绪/占用 |
| 9 | 0x0200 | LAST_BLOCK | 当前读块是末块 |
| 10 | 0x0400 | STREAM_DONE | 所有块已 ACK |
| 11 | 0x0800 | DDR_READ_ERROR | DDR 读取错误 |
| 12 | 0x1000 | FMC/COMMAND_ERROR | FMC/命令访问错误 |
| 13 | 0x2000 | MODE_VALID | FMC 模式检查有效 |

按掩码判断，不要求 STATUS 恰好等于某个固定常量：

```text
启动必需位：         0x2061  （READY/CFG_DONE/CALIB/MODE_VALID）
错误位：             0x1810  （OVERFLOW/DDR_READ_ERROR/FMC_ERROR）
GET 必需位：         0x008C  （DONE/VALID/READ_READY）

可 ARM：  (STATUS & 0x2061) == 0x2061 且 (STATUS & 0x1810) == 0，PENDING == 0
可 GET：  (STATUS & 0x008C) == 0x008C 且 (STATUS & 0x1810) == 0，PENDING == 1
可 ABORT：BUSY == 1 且 DONE == 0，且没有活动 GET/控制握手
```

自动等待时 READY=0、BUSY=1 是正常状态。不要因为 READY=0 就 FINIT、重发 ARM 或报告硬件失败。

### 5.3 TRIGGER 位表与 REASON

| bit | 掩码 | 名称 | 含义 |
|---:|---|---|---|
| 0 | 0x0001 | ARMED | ADC 已开始本次采样，尚未触发 |
| 1 | 0x0002 | HISTORY_READY | 历史足够 |
| 2 | 0x0004 | TRIGGERED | 已触发 |
| 3 | 0x0008 | FINISHING | BUSY 且已触发，正在采样/排空收尾 |
| 4 | 0x0010 | ABORTED | 本次被取消 |
| 5 | 0x0020 | VOLTAGE_REASON | 电压触发原因，DONE 后解释 |
| 6 | 0x0040 | CURRENT_REASON | 电流触发原因，DONE 后解释 |
| 7 | 0x0080 | MANUAL_REASON | 手动触发原因，DONE 后解释 |

REASON 已将原因位右移，不能仍按 0x20/0x40/0x80 判断：

| REASON | 解释 |
|---:|---|
| 0 | 尚未 DONE 或没有原因 |
| 1 | 电压触发 |
| 2 | 电流触发 |
| 3 | 电压和电流同拍触发 |
| 4 | 手动 FORCE |

通用按位解析：`REASON & 1` 电压，`REASON & 2` 电流，`REASON & 4` 手动。
当前手动/自动模式正常情况下不会混合出手动与电压/电流原因。

### 5.4 EVENTS 位表

| bit | 掩码 | 解释 |
|---:|---|---|
| 0 | 0x0001 | START/ARM_ACCEPTED |
| 1 | 0x0002 | COMMAND_REJECTED；不局限于 START |
| 2 | 0x0004 | READ_ACCEPTED |
| 3 | 0x0008 | ACK_ACCEPTED |
| 4 | 0x0010 | ACK_REJECTED |
| 6 | 0x0040 | 本地命令/访问错误 |

事件保持到 CLEAR_EVENTS；一个历史接受事件不代表当前命令成功。
拒绝优先于成功；FORCE 根据 TRIGGERED 判断，ABORT/RELEASE 根据结束状态判断。

### 5.5 完成记录示例

配置：SAMPLES=100000、PRE=30、MODE=1、A≥2500 或 B<1500、两路使能。
下例假设仅 A 导致触发，展示一种完成快照；HISTORY_READY/事件保持位及 DDR 计数仅用于说明，不作为固定比较值：

```text
STATUS:20EC,EVENTS:0001,TRIGGER:0026,ARMED:0,HISTORY_READY:1,TRIGGERED:1,ABORTED:0,REASON:1,CTRL:0,PENDING:1,LENMODE:1,TIME:0,CFG_SAMPLES:100000,PRE:30,MODE:1,VTH:2500,VCMP:0,ITH:1500,ICMP:4,ENABLE:3,ACTIVE_PRE:30000,RATE:100000000,SAMPLES:100000,TOTAL:400000,BLOCKS:49,DDR_WRITE_BURSTS:20000,BURSTS_STABLE:1,HEX_CHARS:800000\r\n*
```

20EC 包含 CFG_DONE、CALIB、MODE_VALID、DONE、VALID、READ_READY，错误位为 0，因此可 GET。
核对 SAMPLES=100000、TOTAL=400000、HEX_CHARS=800000、BLOCKS=49、ACTIVE_PRE=30000。
49 块由 48×8192 字节加末块 6784 字节组成；上位机不按这些块拆 TCP 数据。

## 6. 完整操作流程

每个箭头之间先等待当前命令完整回复；重复 TST 时也一次一条，不连续突发发送。
轮询周期可先采用 50～100 ms，此为上位机调度建议，不是 FPGA 协议约束。需要更快显示时可以缩短，但仍须串行。

### 6.1 首次连接检查

VER → FST → TST。
VER 核对 STM32 软件版本；FST 核对 ID=ADFC、VER=0200、INIT=1、IERR=0、HCLK=168000000、SDCLK=56000000。
TST 检查启动掩码、错误掩码及 PENDING。已有 BUSY 或 DONE 记录时先按状态处理，不盲目重 ARM。

### 6.2 自动触发

先配置 `SAMPLES 100000`、`PRE 30`、`MODE 1`、`VTH 2500`、`VCMP 0`、`ITH 1500`、`ICMP 4`、`ENABLE 3`。
TST 核对配置 → ARM → 收到接受回复 → 重复 TST，直到满足 GET 条件 → 保存本条元数据 → GET。
自动模式不发送 FORCE。等待期间可用户取消并发送 ABORT。等待触发不使用旧 3 秒采集超时。

### 6.3 手动触发

配置长度、PRE 和 MODE=0 → TST 核对 → ARM → 收到接受回复 → 重复 TST 等 ARMED=1、HISTORY_READY=1 → FORCE。
收到 FORCE 回复后继续 TST 等 GET 条件 → 保存元数据 → GET。
阈值/比较/ENABLE 不影响手动触发，但数据仍是两路 A/B。

### 6.4 旧立即采集

SET n,1 → 收到接受回复 → TST 等 GET 条件 → 保存元数据 → GET。
不要把旧程序“SET 之后立刻 GET”的行为直接沿用到 V26；GET 尚未就绪会立即失败。

### 6.5 取消与主动丢弃

BUSY 且未 DONE：ABORT → 收到成功回复 → TST 验证 READY、VALID=0、PENDING=0。
DONE 且未读取、读端空闲：RELEASE → 收到成功回复 → TST 验证记录释放。
若用户点击取消时记录已经刚好 DONE，ABORT 可能拒绝：重读 TST，根据 DONE 改用 RELEASE。
GET 已开始时，取消按钮不能继续发送控制文本；可关闭 TCP，让 V26 执行断线清理，之后重连查询。

## 7. GET 波形传输与上位机解析

### 7.1 字符格式与大小端

发送的是 ASCII HEX，不是原始二进制。每个半字四个大写 HEX 字符，高位在前；先 A 再 B。

```text
A0=0x0123，B0=0x0456，A1=0x0789，B1=0x0ABC
波形正文：0123045607890ABC
```

正文前八个实际 TCP 字节为 `30 31 32 33 30 34 35 36`，即字符“01230456”。
每四字符解析一个 16 位值，无须交换高低字节。将 HEX 文本还原为原始字节时，半字可表示为 `01 23`，属于高字节在前的大端表示。
不要直接用依赖本机小端的 BitConverter 把 ASCII 字节当 ADC 值。

### 7.2 长度和结束标志

GET 前从完成的 TST 保存 `SAMPLES/TOTAL/HEX_CHARS/ACTIVE_PRE/RATE`。
先接收恰好 HEX_CHARS 个波形 ASCII 字节，再接收三字节 `\r\n*`。
例如 100000 对：正文 800000 个字符，成功响应总长 800003 字节。

正文仅包含 `0～9/A～F`。若正文未收满前出现 `\r\n?`，说明 GET 被拒绝或流中途失败；当前记录不能当作成功数据。
若出现非法字符、提前结束、连接关闭或接收进度超时，也按失败处理。
当前 ASCII 格式正文不含星号，但仍按长度接收，不依赖“看到 * 就算完整”。将来改二进制时更不能用星号扫描定位结束。

### 7.3 上位机状态机建议

```text
连接后预检 → 配置 → 等 ARM 回复
手动：轮询历史就绪 → 等 FORCE 回复 → 轮询完成
自动：直接轮询完成（可取消）
完成：保存 TST 元数据 → 发送 GET → 停止文本轮询
GET：累计 HEX_CHARS 个 HEX 字节 → 验证 \r\n* → 记录成功 → 恢复查询
异常：丢弃本次不完整数据 → 查询状态或断线重连恢复
```

正文接收伪代码：

```text
expected = metadata.HEX_CHARS
received = 0
pendingHex = 空缓存
while received < expected:
    从接收缓冲消费数据，保留 recv() 里多余的尾部字节
    正常正文必须是 HEX；若提前遇到错误标志，终止本次记录
    只计入本次正文，不超过 expected
    将数据追加到 pendingHex
    每得到 8 个字符，解析 A=前4字符、B=后4字符（基数16）
    保存/绘制这一对，并保留不足8字符的余数
确认 received == expected 且 pendingHex 没有残留
再消费3字节，必须等于 CR LF *
确认解析对数 == metadata.SAMPLES
```

不要假定 recv() 一次返回 8、512、8192 字节；半字和采样对都可能跨接收包。
最大记录有 160000000 字节 HEX 正文，建议增量解码/写文件，不在 UI 线程一次拼接超大字符串。
命令回复与波形进度使用不同的计时器；触发等待允许无限等待或由用户设置业务期限，业务取消时发送 ABORT。
波形接收超时按链路和持续进度制定，不设置为记录的 200 ms。

### 7.4 编码示例（C#）

```csharp
ushort status = Convert.ToUInt16(fields["STATUS"], 16);
bool error = (status & 0x1810) != 0;
bool readyToGet = (status & 0x008C) == 0x008C
                  && !error && fields["PENDING"] == "1";

// pairText 是已经拼接完整的8个HEX字符，不能直接假设每次recv都够8字节。
ushort a = Convert.ToUInt16(pairText.Substring(0, 4), 16);
ushort b = Convert.ToUInt16(pairText.Substring(4, 4), 16);
// 按协议应有 a <= 4095 && b <= 4095；超出时报告数据格式异常。
```

TST 可按逗号拆字段，再按第一个冒号拆键值，保留字典并按字段名读取，不依赖字段顺序。
只有 TST 的三个位图按基数 16，其余字段按基数 10；不要把 TOTAL 或 CFG_SAMPLES 当十六进制。

## 8. 内部分块、断线与恢复

READ_NEXT/ACK 是 STM32 发给 FPGA 的 FMC 命令，当前没有同名 TCP 文本指令。上位机只发 GET，不自行发 ACK。
V26 每块先校验序号、逻辑偏移、精确长度和 LAST_BLOCK；完整复制到独立 8 KiB 缓冲并完成 FMC 读后发 ACK。
等 ACK_ACCEPTED 且 BLOCK_READY 清除才发送该块。ERR_MEM 只重试当前发送位置，不重复计数。
末块 ACK 后发送完正文，再等 STREAM_DONE、RELEASE、READY，最后输出结束标志。

ACK 释放的是 FPGA 块缓存，不代表上位机已收到。结束标志表示所有正文已经按序提交到 TCP COPY 队列，
不等于电脑应用已保存。上位机必须自行校验正文长度、对数和结束标志，再将记录标为成功。

| 情况 | 上位机处理 |
|---|---|
| 等触发时断线 | 采集不会自动取消；重连先 TST，BUSY 可 ABORT，DONE/VALID 可 GET |
| GET 期间断线 | 丢弃本次不完整数据；V26 本地继续消费/ACK/释放；重连后等待清理结束再查询 |
| 很快断线又重连 | V26 按会话代数隔离，不给新会话发送旧波形或旧控制回复 |
| ARM/START 回复超时 | 不盲目重发；等待控制握手结束后 TST/FST 确认实际状态 |
| BUSY，且不想继续 | ABORT |
| DONE，且不想读取 | 读端空闲时 RELEASE |
| READY 无记录，但 PENDING 因接受反馈丢失仍为 1 | 可 FINIT 恢复，再重新明确配置 |
| DONE、OVERFLOW=1、VALID=0 | 不 GET；读端空闲时 RELEASE 后重试 |
| READ/ACK 异常且 BLOCK_READY 仍占用 | 保存诊断，不强行 RELEASE 或反复 GET；需要处理读端/硬件异常 |

CLEAR_EVENTS 只清事件/本地命令错误，不保证消除 DDR 错误，也不解除记录占用。

## 9. 查询、诊断命令与常见失败

### 9.1 VER / FST / FREG / FINIT

| 命令 | 用途与期望 |
|---|---|
| VER | 返回 `V1.0.13 (V26)\r\n*`；这是 STM32 软件版本 |
| FST | FPGA 初始化、状态、最近操作/传输诊断及 TCP 流控计数；正常初始化应 ID:ADFC、VER:0200、INIT:1、IERR:0 |
| FREG | FMC 配置与前四个 FPGA 半字联调；期望 SDCLKF:3、RPIPE:2、RBURST:0、CAS:3、CFGOK:1、R00:ADFC、R02:0200 |
| FINIT | 重新执行 FMC 初始化并检查签名；成功 `\r\n*`；不作为每次采集必需命令，不用于取消正常 BUSY/保留记录 |

FMC 参数保持 HCLK=168 MHz、SDCLK=56 MHz、CAS=3、RPIPE=2、RBURST=0、BL=1。
FREG 可以在初始化失败时用于联调；FST 是诊断信息，不是简化的采集结果接口。

**同名字段在 FST 与 TST 中不完全同义：** 当前 V26 的 FST `TOTAL` 实际打印累计已交给 TCP 的原始等效字节数，
`BLOCKS` 打印累计已 ACK 块数；TST 的 TOTAL/BLOCKS 才是完成记录的总长度/总块数。
上位机获取 GET 接收长度必须使用 TST，不能使用 FST 的 TOTAL。
FST 的 SET 字段为 `SET:时间,使能`，通用逐逗号键值解析器需特殊处理；TST 没有这个问题。
V26 沿用 V24 的精简 FST：没有 V22 的 ST* TCP PCB 深度快照及重传字段。先记录 FST 的简要 GET/TCP 诊断，再处理失败记录。

### 9.2 FST 错误码

IERR（初始化）：

| 值 | 含义 |
|---:|---|
| 0 | 初始化无错误 |
| 1 | SDCLK 超出允许范围 |
| 2 | FMC BUSY 超时 |
| 3 | ID 不匹配 |
| 4 | VERSION 不匹配，应为 0200 |
| 5 | MODE_VALID 未满足 |
| 6 | SDCLK 不等于目标 56 MHz |

SETERR（旧 SET 和部分控制反馈诊断）：

| 值 | 含义 |
|---:|---|
| 0 | 无已记录错误 |
| 1 | FMC 未就绪 |
| 2 | 时间/语法范围错误 |
| 3 | 时间配置读回错误 |
| 4 | 状态错误（保留定义） |
| 5 | 启动前提不满足 |
| 6 | 清事件反馈超时 |
| 7 | 命令拒绝 |
| 8 | 命令结果反馈超时 |
| 9 | 记录被占用/忙 |
| 10 | 自动组间隔尚未届满 |

不是所有新配置命令的本地拒绝都更新 SETERR；该字段可能保留历史值，不能当统一的最后错误接口。

GETERR：0 无错误，1 FMC 未就绪，2 活动传输忙，3 TCP 断线，4 状态/元数据异常，5 没有可读完成记录，6 保留的未接受启动定义。
TXERR：0 无错误，1 状态错误，2 READ_READY 超时，3 块准备超时，4 块元数据异常，5 ACK 拒绝，6 ACK 超时，
7 STREAM_DONE 超时，8 RELEASE 超时，9 总长度异常，10 旧采集完成超时保留值（V26 不走该等待状态），11 TCP 发送异常。

### 9.3 排查表

| 表现 | 优先核对 |
|---|---|
| 命令完全无回复 | 是否发了真实 CR；是否正在握手/GET 导致命令被忽略；是否断线或回复丢失 |
| 参数配置返回 ? | 参数范围、十进制格式、尾部垃圾、初始化；TST 核对实际值 |
| ARM/ACQ 返回 ? | INIT、启动掩码、错误位、PENDING、MODE/ENABLE 组合，以及 TST 的 GAP_LEFT_MS；SETERR:10 表示组间隔未到 |
| FORCE 返回 ? | 本次是否手动，是否已 ARM/HISTORY_READY，是否已经触发或 DONE |
| ARM 后 READY=0 | 结合 BUSY/TRIGGER 看等待状态；不要仅凭 READY=0 判错 |
| 自动长时间不触发 | HISTORY_READY、阈值码、比较方向、通道使能和实际输入；允许业务取消 |
| PRE=100 看不到触发样本 | 正常，触发样本不在记录内，ACTIVE_PRE=N |
| GET 返回 ? | DONE/VALID/READ_READY、PENDING、错误位；不能提前 GET |
| GET 接收长度差一倍 | 原始字节 TOTAL 和 HEX 字符数 HEX_CHARS 混淆 |
| 波形值完全不对 | ASCII 解析、每4字符一半字、A/B顺序、是否错误交换字节 |
| GET 停顿 | 保存 FST 的 GET/TCP 摘要；V26 使用 V24 的网络路径，当前 FST 没有 ST* 深度快照。若现场仍停顿，需要抓包和上板诊断 |

当前 V26 控制清事件与控制结果分别使用约 1 秒的进展期限，不是触发等待期限。
上位机可先用 5 秒作为普通命令回复超时并调试调整；超时必须做状态核对，不能自动无条件重发 ARM/FORCE。
GET 的读端阶段有内部超时，TCP 背压可持续等待；上位机独立监测接收进度。

## 10. SOP 文件使用方式
