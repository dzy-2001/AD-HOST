# 快速开始

## 连接 STM32

1. 电脑网卡与 STM32 网络配置需可互通。
2. 启动 AD-HOST，输入真实 STM32 IP 和 TCP 端口（界面默认地址仅是示例）。
3. 选择有足够空间的保存目录，默认分卷 1024 MiB、队列 64 MiB 即可开始。
4. 点击“连接并开始保存”。连接成功后显示“正在接收并保存”。
5. 如设备需要启动指令，在发送区域按实际协议输入后发送。

没有数据时速度为零并不一定是故障：设备可能需要先收到启动指令。

## 发送指令

- HEX：例如实际协议要求的 `AA 55 01 FF`，会发送四个字节，不是这段文字。
- UTF-8：按 UTF-8 编码发送输入的文本。
- 结束符 NONE 表示不添加；LF 为 0A，CR 为 0D，CRLF 为 0D 0A。
- 示例仅用于解释编码，**不是 STM32 的真实控制指令**。
- 不支持 0x 前缀、逗号分隔或不完整的半字节。
- 如协议包含长度和校验码，应将完整指令都填入。
- “已排队”不是已发送，“已提交 TCP 发送”不是设备已执行；设备回复按真实协议确认。
- 收到的指令回复与采集数据一起保存。

## 看哪些指标

- 当前 MB/s：程序实际收到的字节速度。
- 累计接收 / 写入：正常结束后应相等，同时 session.json 的 storage_complete 应为 true。
- 待写入：若持续增大，说明写盘处理落后；达到上限后会反压设备。
- 状态与异常：连接错误、发送失败、保存失败都会显示。

文件容量以 MiB 显示，速度以十进制 MB/s 显示；两者数值不能直接等同。

## 结束与找文件

优先发送设备定义的停止指令，确认设备结束后再点击“断开并完成保存”。也可以直接断开，但尚未进入程序的数据可能不再收到。等待“已结束”后，界面路径对应的目录里包含原始 .bin 和 session.json。

下一次连接会创建新的目录，不覆盖前一次数据。程序不自动重连或重发指令。

## 常见问题

- **连接失败**：检查 IP、端口、设备是否正在监听、网线、网段、防火墙与其他上位机是否占用连接。
- **连接成功但 0 MB/s**：确认设备是否需要启动指令，指令编码、结束符和校验码是否正确。
- **预览看起来有断帧**：预览仅是最新接收片段，TCP 接收边界不是数据帧边界；查看完整文件并按协议解析。
- **保存失败或磁盘满**：本次采集会停止并标记失败；释放空间后重新采集。不要把不完整文件当成完整记录。
- **缓冲一直增长**：尝试更快的本地磁盘、降低设备速率；增加缓冲只能吸收短时波动。
- **无法启动 exe**：完整解压下载包并保留 _internal 目录，或使用 Python 源码启动。
