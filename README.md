# AD-HOST

面向 STM32 的 Python TCP 客户端：**连接、发送指令、接收原始字节、保存文件、测量传输速度**。

初版使用 Python 标准库与 Tkinter，无第三方运行依赖。接收、写盘和发送使用独立后台线程；界面每 200 ms 更新，速度约每秒采样，不逐包打印或追加十六进制日志。

> 这是可用于初步联调的通用字节流采集工具。尚未在实际 STM32 / FPGA 链路上验证，不承诺某个吞吐量或端到端无丢失。

## Windows 使用

### 无需安装 Python

1. 打开仓库的 **Actions → Test and build Windows app**。
2. 选择最新成功运行，在 **Artifacts** 下载 **AD-HOST-Windows-x64**（私有仓库需要登录）。
3. **完整解压**，双击 `AD-HOST.exe`。保留同目录下的 `_internal` 文件夹。
4. 输入 STM32 的 IP 和 TCP 端口，选择保存目录，点击“连接并开始保存”。

构建产物保留 30 天，过期可在 Actions 手动重新运行。程序未做代码签名。

### 从 Python 源码启动

需要 Python **3.10 或更高版本**，Windows 安装时保留 Tcl/Tk 和 Python Launcher。

```console
python run.py
```

也可以双击 `start.bat`（需要 `py` 启动器）。无需运行 `pip install`。Linux 通常需另外安装发行版的 Tkinter 包；桌面主要面向 Windows。

详细步骤见 [快速开始](docs/QUICKSTART.md)。

## 功能

- 手动输入设备 IP 和端口，电脑主动建立 TCP 连接。
- **连接即开始保存**，包括设备主动发送的数据和指令回复。
- HEX 指令：`AA 55 01 FF` 或 `AA5501FF`；严格检查完整字节。
- UTF-8 文本指令；可追加 NONE / LF / CR / CRLF，默认 NONE。
- 不自动添加帧头、长度、校验码或设备特有命令；单条最多 4096 字节。
- 与接收共用同一条连接，发送在后台执行，不阻塞界面。
- 当前速度、近 10 秒平均、本次平均、最高采样区间速度。
- 接收量、写入量、待写入量、发送量。
- 16 / 64 / 256 MiB 接收队列，默认 64 MiB。
- 256 / 1024 / 4096 MiB 文件分卷，默认 1024 MiB。
- 最多 256 字节的最新片段预览，可关闭。
- 停止时完成已经进入程序的字节的保存；错误与会话信息记录到 JSON。
- 断开后手动重连，创建新会话；**不会自动重发指令**。

## 数据文件

每次连接在所选目录下创建一个独立子目录：

```text
20261009_154400_0123abcd/
  session.json
  part_00001.bin
  part_00002.bin
  ...
```

- `.bin` 是 TCP 接收到的原始字节，没有文本转换，也没有人为插入分隔符。
- 按文件名顺序拼接各分卷，可恢复本次程序接收到的字节流。
- 分卷边界和 `recv` 边界**都不是设备数据帧边界**；分卷可以切开设备帧。
- 指令回复也会进入数据文件，需在后处理时按照真实协议识别。
- `session.json` 包含地址、时间、各分卷大小、收发计数、结束原因和错误。
- 会话开始时就写入初始 JSON，正常结束后更新。程序崩溃或断电可能只留下初始记录；不要把它当成完整采集。
- `storage_complete=true` 只表示本程序已接收的字节全部写入并成功完成 flush / fsync；**不证明 FPGA 产生的数据全部收到**。
- `source_completeness` 固定为 `not_verified`。目前没有设备帧序号、发送端计数或应用层结束握手，无法自动证明端到端完整性。
- 实时“写入量”是被文件写接口接受的字节数，包含尚在系统/文件缓冲中的数据。会话正常结束或切卷时才 flush / fsync。
- 保存异常时，计数可能包含缓冲中未落盘的字节；必须检查错误和 `storage_complete`，不能仅比较两个计数。

## 停止采集

如果设备协议有停止发送指令，推荐：

1. 按设备协议发送停止指令。
2. 确认设备的结束标记 / 回复，并确认数据流已经结束。
3. 点击“断开并完成保存”，等待状态变成“已结束”。

直接点击断开只保证尽力保存**已由 recv 返回给本程序**的数据；尚在设备、网络或操作系统接收缓冲中的字节可能不再接收。空闲几秒也不能单独证明设备已结束。

网络异常时同样会完成已接收数据的保存，但会明确标记错误。发生磁盘写入错误时停止采集，不继续静默丢弃。关闭窗口时会询问并等待保存完成，强制结束进程不具备此保证。

## 速度和缓冲的含义

- MB/s 使用 1,000,000 字节；Mbps = MB/s × 8。
- 文件容量和内存容量使用 MiB（1,048,576 字节）。
- 速度按照单调时钟与实际字节差计算，不假设 GUI 定时器精确。
- 近 10 秒速度由采样点估算；采样间隔较大时窗口可能稍长于 10 秒。
- 本次平均包括连接等待和结束写盘时间；结束后速度保留最后的统计值。
- 最高采样区间速度通常对应约一秒区间，不代表毫秒级峰值或网卡线速。
- 预览是最新一次接收的末尾片段，不是完整历史，也不能用于判断帧完整。
- 待写入量包含队列、写入中的块和接收线程持有的块，最多比队列容量多两个接收块（默认每块 256 KiB）。
- 队列满时接收线程等待，借助 TCP 反压限制发送；不以丢弃应用数据来维持速度。
- 长期写入慢于输入无法靠增大缓冲解决；STM32 和 FPGA 仍需正确处理反压。
- “已提交发送”表示 sendall 成功交给 TCP，不是设备业务层确认。发送失败可能已发出部分字节，故不自动重试。
- 原始载荷未做解析、重排、去重或解压。TCP 提供有序字节流，但上游链路的完整性仍需设备协议校验。

## 本机模拟联调

先启动本机测试发送端：

```console
python tools/tcp_simulator.py --port 5000 --mib 64 --mbps 10
```

再启动 AD-HOST，连接 `127.0.0.1:5000`。约以 10 MB/s 发送 64 MiB 的确定性二进制模式，发送完成后关闭连接。期间可发送指令，模拟器会打印收到的字节片段。

预期累计接收和保存均为 **67,108,864 字节（64.00 MiB）**。命令参数 `--mbps` 的单位是 MB/s，0 表示不主动限速。此测试评估本机软件路径，不能代替真实硬件链路测速。

## 测试与构建

```console
python -m unittest discover -s tests -v
python tools/gui_smoke.py
```

第二条需要可用桌面和 Tk。自动测试在 Ubuntu 和 Windows 运行；GUI 冒烟测试在 Windows 运行，实际连接本机 TCP 服务、发送 HEX 指令、核对保存内容并关闭窗口。

覆盖：任意接收分段、二进制逐字节一致性、精确分卷、双向通信、主动停止后保存、慢磁盘反压、写盘失败、输出路径失败、拒绝连接、输入校验和测速。

Windows 打包：

```console
python -m pip install pyinstaller==6.16.0
python -m PyInstaller --noconfirm --clean --windowed --onedir --name AD-HOST --collect-submodules tkinter run.py
```

运行 `dist/AD-HOST/AD-HOST.exe`。打包工具不是源码运行依赖。

## 后续接入真实协议所需信息

设备 IP / 端口；启动和停止指令；帧头、长度和校验规则；序号或采样计数；设备处理 TCP 反压的方式。确认这些信息后可加入完整性统计、指令快捷按钮及离线解析，接收保存主路径无需先做业务解析。
